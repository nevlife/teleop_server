# Teleop v2 server

The v2 server never decodes or transcodes media. `teleop-v2-server` pairs one
native rover with one native operator over WebSocket signaling. coturn relays
their encrypted, already-compressed SRTP/RTCP and data-channel packets.

## Ports

| Port | Purpose |
|---|---|
| TCP 13437 | `/ws` signaling and `/healthz` |
| UDP 13437 | TURN allocation endpoint |
| UDP 50000-50049 | TURN relay allocations |

Forward all three entries at the home router. TCP and UDP 13437 are separate
sockets and can use the same number.

Copy `deploy/coturn/turnserver.conf.example` to a machine-local configuration,
set its `external-ip=PUBLIC_IP/PRIVATE_LAN_IP`, and start coturn with that file.
Remote peers must receive the public address, for example:

```bash
export TELEOP_TURN_URL='turn:YOUR_PUBLIC_HOST:13437?transport=udp'
```

## Development with a virtual environment

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[test]'
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 pytest teleop_v2_server/tests
teleop-v2-server
```

Disabling pytest plug-in autoload keeps ROS 2 plug-ins exported through the
parent shell's `PYTHONPATH` out of this otherwise isolated Python test run.

The default install contains only the v2 signaling runtime. To run the retained
Zenoh implementation, install it explicitly with `pip install -e '.[legacy]'`.

## Docker deployment

Create the local environment file and set the public host and TURN password:

```bash
cp .env.example .env
docker compose up -d --build
docker compose ps
```

The signaling container publishes TCP 13437. coturn uses host networking, as
recommended for its UDP relay port range, and binds UDP 13437 plus UDP
50000-50049. Forward those exact TCP/UDP ports at the home router. The default
`DETECT_EXTERNAL_IP=yes` asks the official coturn image to discover the public
IPv4 address; replace it with an explicit coturn `--external-ip` option if the
router/network requires a public/private address mapping.

The first frame on `/ws` must be:

```json
{"type":"hello","protocol_version":2,"role":"rover","robot_id":"rover-01"}
```

The other allowed role is `client`. A second peer with an occupied role is
rejected. Once paired, the rover receives `create_offer: true`; SDP and ICE
messages are then forwarded unchanged to the counterpart.

There is no application login in this development milestone. WebRTC still
uses mandatory transport encryption, and coturn uses one static deployment
credential to avoid operating an unrestricted public relay.
